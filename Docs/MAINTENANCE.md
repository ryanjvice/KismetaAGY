# Docs Maintenance Guide

This document describes how the `Docs/` folder is organized and how to keep it up to date.

---

## Source of truth

All rule text and card data lives in two canonical files:

| File | Contents |
|------|----------|
| [`_source/Kismeta_GameGuide.md`](_source/Kismeta_GameGuide.md) | Full rulebook: setup, phases, strategy, glossary, lore |
| [`_source/Kismeta_CardReference.md`](_source/Kismeta_CardReference.md) | All card data: Major Arcana, Crucible groups, Minor Arcana suits |

**Edit only these two files** when updating rule text or card effects. Everything else under `Docs/` (except the files listed below) is generated.

---

## Generated vs hand-maintained

| Path | How to edit |
|------|-------------|
| `_source/Kismeta_GameGuide.md` | **Edit directly** — canonical source |
| `_source/Kismeta_CardReference.md` | **Edit directly** — canonical source |
| `docs-split.manifest.json` | Edit when adding, removing, or renaming a split output file |
| `README.md` | **Hand-maintained** — navigation index and dev notes |
| `Cards/README.md` | **Hand-maintained** — card doc index |
| Everything else (`Rules/`, `Reference/`, `Lore/`, `Cards/**`, `Glossary.md`) | **Generated** — do not edit directly |

Generated files begin with an autogen banner comment:

```
<!-- AUTO-GENERATED from _source/Kismeta_GameGuide.md -->
<!-- Output: Rules/phases/spring.md -->
<!-- Do not edit this file directly. Edit _source/... and run: npm run docs:sync -->
```

If you edit a generated file manually, your changes will be overwritten the next time you run sync.

---

## Day-to-day workflow

1. Open `_source/Kismeta_GameGuide.md` or `_source/Kismeta_CardReference.md`.
2. Make your edits and save.
3. From the repo root, run:

   ```bash
   npm run docs:sync
   ```

4. Review the output in your terminal — each generated file is listed as `WROTE` or `ERROR`.
5. Commit **both** the source file and the generated outputs so the split docs are visible in GitHub and Cursor without requiring others to run sync.

---

## Adding a new split section

1. Add a new entry to `docs-split.manifest.json`:

   ```json
   {
     "source": "Kismeta_GameGuide.md",
     "output": "Rules/my-new-section.md",
     "start": "## MY NEW HEADING",
     "end": "## NEXT HEADING AFTER IT",
     "title": "# My New Section"
   }
   ```

   The `start` and `end` values must exactly match the beginning of a heading line in the source file (the match uses `startsWith`, so trailing text and emoji are fine).

2. Add a link to the new file in the hand-maintained `README.md`.
3. Run `npm run docs:sync`.

---

## Renaming a section in the source

If you rename a heading in a `_source/` file that is referenced as a `start` or `end` anchor in the manifest, sync will fail with a clear error. Update the manifest entry's `start`/`end` to match the new heading, then re-run sync.

## Known discrepancies in the source material

These inconsistencies exist in the source files. They are preserved as-is in generated output; reconcile them in a future rules pass:

| Issue | Locations |
|-------|-----------|
| Base Harvest count: **3** in phase rules tables vs **2** in Glossary | Spring phase section; Glossary entry for "Harvest" |
| Major Arcana count: **12 Adept / 10 Fate** in Components vs **11 / 11** in Glossary | Components section; Glossary entry for "Major Arcana" |
| Court rank naming: **Princess** in Card Reference vs **Page** in Game Guide | Minor Arcana suit files; Game Guide spring/harvest rules |
